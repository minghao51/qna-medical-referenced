### Initial wider-test storage caveat

The first focused/wider verification invoked the existing `test_search_hypothetical_questions_only_returns_query_relevant_matches`, which constructs `ChromaVectorStore(collection_name="test_hype_search")` without temporary persistence. It cleared/repopulated that **test collection** in the configured `data/chroma` directory. The configured served collection was `medical_docs`, not `test_hype_search`; the test did not target that collection. Do not describe the initial run as having zero existing-directory writes, and do not delete/restore the user's database to hide this side effect.

Final verification redirects Chroma persistence to a fresh temporary directory and disables remote Chroma selection before importing application modules. This is a test-runner isolation measure, not a storage migration. Broad test runs must retain this protection until the pre-existing fixture issue is separately repaired. HTTP tests were not run in this slice: their module-level rate limiter also needs an explicitly isolated SQLite path before broader app validation.
