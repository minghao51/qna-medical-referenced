## Implementation

- `src/infra/llm/{qwen_client,gemini_client,litellm_client}.py`: direct existing stream loops now retry only recognized transient transport/timeout errors or HTTP 408/429/5xx, **before any nonempty content**. Auth/validation/unknown failures fail immediately. Set the emitted flag before yielding; no restart/fallback after emitted content. Empty/usage-only chunks do not set it, including LiteLLM chunks with no choices.
- Existing `settings.retry.max_retries` remains the **total attempt count**, normalized to at least one (default three), not additional retries. Backoff stays exponential but nonnegative/capped at 30 seconds. Each attempt has a 30-second active-producer budget across SDK creation/reads. Timeout scopes end before yielding; the deadline is extended by consumer-suspension elapsed time. A slow consumer therefore neither gets cancelled by the producer's timer nor spends its upstream budget.
- Disable native retries **per stream call**, not by changing shared clients: Qwen `with_options(max_retries=0, timeout=30.0)`; Gemini per-request `HttpOptions(timeout=30000, retry_options=HttpRetryOptions(attempts=1))`; LiteLLM `max_retries=0, num_retries=0, timeout=30.0`. LiteLLM rejects conflicting process-global retries/fallbacks rather than mutating them or silently routing elsewhere. No new model/route fallback.
- Each attempt `finally` calls its owned returned stream's public cleanup hook: Qwen `close()`, Gemini `aclose()` when offered by its public iterator, LiteLLM `aclose()`. Ordinary cleanup failures log a neutral provider-specific message without SDK text; they neither replace the primary outcome nor cause retry on their own. A cleanup attempt is not proof of successful physical release after failure.
- `src/usecases/chat.py`: `aclosing` owns the client generator through completion, ordinary error, explicit early close, or ordinary asyncio task cancellation. **Generation failures no longer save the user or accumulated assistant fragment into ordinary history.** Successful history saves remain the existing two writes. Direct consumers still receive an error terminal then `UpstreamServiceError` on the next iteration.
- `src/app/routes/chat.py`: `aclosing` owns the usecase generator. Guard against content or additional terminal events after the first terminal; preserve `content`, `done`, `sources`, `pipeline`, sanitized `error/error_code`, and request-ID fields. Existing error-after-terminal handling does not emit a second terminal.
- Touched usecase/route streaming failure logs no longer use raw exception tracebacks/text or raw session identifiers/cookies. Request correlation/error code remain. This is not a full privacy audit; nonstream/SDK logging and export policy remain separate gates.

### Intentional behavior changes

A partial stream ends with the existing sanitized error terminal rather than a replayed prefix or a normal completed historical turn. Even a pre-token generation failure is discarded rather than leaving an orphan user entry. Native retry multiplication is disabled for streams; active-producer timeout is now finite for all three adapters. Conflicting LiteLLM global retry/fallback settings fail closed. Consumer backpressure is **not** an upstream timeout.

No history migration/backfill/cleanup occurs. Previously saved partial turns are not silently rewritten; old stored-data semantics remain historical.
