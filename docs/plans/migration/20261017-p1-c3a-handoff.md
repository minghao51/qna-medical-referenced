## Delivered boundary

### Nonstream methods

- All twelve text/structured × sync/async methods across Qwen, Gemini and LiteLLM use the same transient-only policy as existing streams: recognized timeout/network/protocol failures and HTTP 408/429/5xx. Authentication, permission, validation/schema/JSON/empty-response and unknown errors fail immediately. Cancellation is not retried.
- `settings.retry.max_retries` remains the **total attempt count**, normalized to at least one, not additional retries. Nonnegative exponential backoff is capped at 30 seconds.
- Request timeout and SDK retry overrides are requested per call (the default Gemini aiohttp exception path below is not controlled by that override): Qwen `.with_options(max_retries=0, timeout=30)`; Gemini `HttpOptions(timeout=30000, retry_options=HttpRetryOptions(attempts=1))`; LiteLLM `max_retries=0, num_retries=0, timeout=30`. LiteLLM rejects the same known conflicting global retry/fallback settings as streams before calling the SDK; the wrapper does not mutate them.
- Async awaited producer attempts also have `asyncio.timeout(30)`; no timeout scope spans a generator yield. Synchronous SDK timeouts are not a hard wall-clock/thread deadline. No application-wide hard request deadline is claimed.
- Touched wrapper logs contain fixed provider/attempt/delay information, not raw SDK exception text/tracebacks, prompts, context or credentials. This is not a privacy certification of third-party SDKs or other application logging.
- Messages, models/providers/defaults, temperature 0.7, token limit 2048 and structured response schemas are unchanged. No corrective regeneration/fallback or framework abstraction was added.

### Returned public stream cleanup

- Each returned stream's public `close`/`aclose` awaitable becomes one owned same-loop future. Awaitable support includes native async-generator `aclose()` objects, not only coroutine functions.
- First await is cancellation-observing; after cancellation, drain under AnyIO shielding, tolerating repeated explicit asyncio cancellation without busy-polling. Consume ordinary cleanup failures neutrally and re-raise cancellation. A public close that itself raises cancellation is not converted to success/retry.
- Existing unchanged usecase/route `aclosing` and C2 `turn` ownership consequently retain same-session admission until public cleanup settles. Concurrent same-session turns/history clear remain rejected while unrelated sessions can proceed. Failed/cancelled generation emits no successful terminal or historical pair; complete-pair admission/commit semantics are unchanged.
- Shared SDK clients are not closed per request. Existing stream retry-before-content, no-prefix-replay, active-producer budget and consumer backpressure behavior remain unchanged.
- Public cleanup can wait indefinitely. Native Gemini inner HTTP release, hard shutdown/charge reversal, arbitrary external cancellation of owned children, forced thread termination and broader retrieval/non-commit request-worker ownership are not guaranteed.
