## Implementation and cancellation contract

- `src/rag/index.py`: `initialize_vector_store_async` offloads the entire synchronous initialization critical section to one private helper. That worker acquires the existing process-local thread lock, resolves state/signature inside it, obtains the store, and invokes synchronous ingestion without awaiting under the lock. Async callers no longer block the event loop waiting for this lock or store setup.
- The public sync initializer retains its existing running-loop guard and `asyncio.run` wrapper around the canonical async entry. Same-loop async calls and sync callers on other threads/event loops share the same thread lock; no new global loop-bound async lock, framework, or duplicate pipeline.
- Cancellation is **cooperative at the worker's post-lock admission checkpoint**. If the async caller observes cancellation and sets its per-call event before the checkpoint, the worker skips all state/store work, including a queued forced rebuild. Once the worker passes that checkpoint, later cancellation stops the caller's wait but cannot revoke work, even if the first store access has not happened yet. The worker retains the lock until completion/failure, preventing overlap.
- This does not guarantee that the instant `Task.cancel()` is requested wins against worker admission: delivery on the event loop can lag. It does not kill a thread, undo ingestion/provider charges, or prove app shutdown drains active work safely.
- `tests/unit/rag/test_runtime_index_initialization.py`: seven new cases use synthetic stores/ingestion, fresh runtime state, event gates, and a bounded real thread-lock wrapper. Timeouts prevent regressions from hanging pytest; ordering assertions, not elapsed-time targets, prove responsiveness and serialization.
- `.planning/codebase/ARCHITECTURE.md`: update initialization delegation to match the single off-loop critical section. Migration statuses/requirements and this handoff record the accepted contract.
