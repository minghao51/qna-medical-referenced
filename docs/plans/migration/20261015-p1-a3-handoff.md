# P1-A3 — Off-loop retrieval and native-async HyDE handoff

**Status:** Approved and verified, 2026-10-15. Phase 1 remains incomplete.
**Approval:** Owner's “proceed with next” after the bounded proposal to offload retrieval/search/reranking with offline responsiveness tests. Scope also corrects HyDE's synchronous generation call inside its async function, necessary for the same R01 path.
**Requirements:** R01 retrieval/async boundary subset; preserve R00 seams and existing ranking/source behavior. No live-provider, whole-app lifecycle, clinical-quality, throughput, or default-switch claim.

## Changes

- `src/rag/runtime.py`: await offloaded store access, synchronous lexical/medical preparation, HyPE lookup, and rerank/diversification. Preserve stage order, empty-query/truncation behavior, filtering, sources, meaningful trace fields, and the sync path. A module-local thread lock surrounds shared reranker lookup plus loading/prediction; async calls acquire it only in the worker. No generic executor or parallel pipeline.
- `src/rag/retrieval.py`: offload the existing sequential traced search/merge batch, including synchronous query-embedding operations underneath the store. Copy caller-supplied expanded queries before handing them to the worker; an explicitly empty list still skips expansion/generation/search.
- `src/rag/query_expansion.py`: offload preparation when direct async callers have no pre-expanded list. The already-prepared runtime path does not expand twice.
- `src/rag/hyde.py`: await existing `LLMClient.a_generate()` on the owning event loop instead of synchronous `generate()`. No new client/provider selection or sync fallback. Keep prompt, cleaning/truncation, and ordinary-error fallback; cancellation propagates.
- `tests/unit/rag/test_async_retrieval.py`: 25 new real-orchestration regressions with fresh runtime state, synthetic leaf dependencies, a no-ingestion guard, bounded event gates, context-variable/thread checks, and real ranking/diversification logic. The cold-reranker case uses the real cache factory with fake constructor/load/prediction leaves and an instrumented bounded real lock.
- `tests/unit/infra/test_hyde.py`: update five existing mocks to the async method. Only the eleven safe existing cases listed below were selected; this does not convert the module's other legacy tests into offline tests.
- Architecture and migration checklists updated; prior P1-A1/P1-A2 changes retained.

## Cancellation, identity, and limits

- Cancellation stops caller waiting and prevents later orchestration stages. It **cannot terminate a started synchronous stage**, including the rest of its sequential candidate batch or a worker already waiting on the reranker lock. Thread-pool queueing and the P1-A2 initialization admission checkpoint retain their own semantics. No guarantee of undoing work, model/embedding charges, immediate pool shutdown, or process termination.
- Tests release all gates and drain tasks; cancellation cases own/join the thread executor so workers cannot leak into the next fixture. This is test cleanup, not an implementation of app lifecycle ownership.
