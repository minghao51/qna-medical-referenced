# P1-A4 — Synthetic HTTP/SSE lifespan and app-owned cleanup

**Status:** Approved and verified, 2026-10-15; Phase 1 remains incomplete.
**Approval:** Owner's “proceed” after the proposal for synthetic HTTP/SSE lifespan verification and startup-failure cleanup.
**Requirements:** R01 app-owned lifecycle/transport subset. No clinical, public-deployment, live-provider, throughput, or universal worker-shutdown claim.

## Changes and ownership

- `src/app/factory.py`: `try/finally` now covers dependency acquisition and the yielded lifetime. Initialize through the canonical async worker first, then publish the warmed store singleton; no cold Chroma construction on the startup loop. Capture the exact client constructed at this composition edge, not a later replacement in `app.state`.
- Lifespan-owned initialization and cleanup tasks are shielded and drained across repeated caller cancellation before resets. A cancelled startup waits for its admitted synchronous build to finish/fail; caller cancellation stays primary if that drained build fails. This avoids publishing readiness after failed-startup cleanup has reset the factory/state.
- Cleanup attempts the captured client's optional `aclose()`, logs ordinary close failure without raw SDK exception details, clears dependency references, and resets logical factory/runtime state even on exceptional exit. Ordinary cleanup errors do not replace the startup/body failure; a close attempt is not a guarantee that an SDK reporting failure actually released all resources.
- `src/infra/llm/qwen_client.py` and `gemini_client.py`: add native async close hooks; async SDK closure stays on the owning loop, and sync SDK closure runs off-loop in a `finally` so it is attempted even if async closure fails. The existing `LLMClient` generation protocol is unchanged. LiteLLM's wrapper owns no transport session; its absent optional hook is supported and global library caches are not closed.
- `tests/integration/app/test_lifespan.py`: 18 new real-lifespan cases. Keep actual app middleware/router/use-case/retrieval/initializer/factory execution, fake only store/ingestion/generation leaves, and use real temporary history/rate-limit SQLite files. Cover ready/cold startup with/without traces, six startup failure points, exceptional lifetime exit, replacement ownership, cleanup-error handling, no-hook clients, and repeated cancellation during startup and cleanup.
- `tests/unit/infra/test_client_cleanup.py`: six mocked SDK close cases cover both wrappers, success and async/sync failures, order, and thread affinity. No SDK construction or network required.
- Architecture/migration checklists updated. Prior P1-A1–P1-A3 code and dirty-tree changes preserved.
