## Implemented contract

### Attempts and identity

- New manifests/summaries carry `artifact_contract_version: 1`. Existing measurement semantics remain `measurement_contract_version: 1`; retrieval formulas and clinical-quality validity are not upgraded by this marker.
- `ArtifactStore` adds an opaque UUID execution ID to the existing timestamp/name directory shape. Every assessment creates exactly one store. The earlier `_seed_manifest()` second-store bug is fixed: initial manifest, final artifacts, cache parent and returned run directory now share one attempt.
- A configuration fingerprint includes the selected configuration, input provenance and bounded source/lock snapshot. Top-level output location, display name, dataset path spelling and `force_rerun` are excluded. It is explicitly **not** a complete semantic fingerprint: nested experiment metadata/effective settings and corpus/index semantics are not fully resolved.
- Before configuration hashing/persistence, assessment serializes one plain configuration snapshot and validates that same snapshot, rejecting recognized credential-shaped keys, SecretStr-like values and URLs containing userinfo/query/fragment with a fixed neutral error. Tests cover nested/Pydantic values, snake/dash/camel credential/token fields and URLs. This is conservative preflight, not arbitrary-text secret detection or a full effective-configuration allowlist; designated config content must still be non-secret.
- `identity.status` is `unverified`; `semantic_fingerprint` is `null`; index identity has a fixed reason (`consistent_collection_snapshot_not_implemented`); `reuse_eligible` and `promotion_eligible` are false. Source capture failure does not invent a verified identity. The existing raw-directory stat snapshot is explicitly labeled metadata-only/unverified.
- New run-index entries are keyed by execution ID, not the configuration fingerprint, so repeated attempts remain distinct. The legacy `run_identity`/`dedup` fields remain for readers, but `dedup.reused_existing_run` is always false for new assessments. The legacy reuse helper excludes versioned manifests; its old-artifact lookup behavior is retained only for compatibility.

### Source provenance, not a runtime/index snapshot

- `reporting.source_provenance()` records Git revision, dirty state including untracked files, `uv.lock` content digest, and a versioned digest of names/bytes of regular `src/**/*.py` files, tracked and untracked. It uses the repository derived from the module location, not an arbitrary caller CWD.
- It never returns Git status/path listings, source contents, credential values or their hashes. Designated source/lock bytes are read; `.env`, settings YAML, arbitrary configuration/data/output files are not included in its content digest. This assumes designated Python source and the lockfile are non-secret; it is not secret detection for secrets embedded in source.
- File/directory descriptors, non-following opens, before/after metadata/inventory, lock rehash and Git state checks reject detected drift, symlinks, unavailable scope/Git/lock and read failures with fixed neutral reasons. Detached Git HEAD is supported. Global Git configuration/fsmonitor behavior is disabled for capture; synthetic Git test repositories also disable user/system config and hooks.
- A `verified` **source** status means only a bounded stable best-effort capture. It is not an atomic whole-tree snapshot, proof of the actually imported/runtime code, full dependency environment identity, actual index identity, complete effective role configuration, cross-run comparability, or promotion permission.

### Fresh execution and diagnostic cache records

- Automatic complete-run reuse is removed from assessment execution. Repetitions always execute a new attempt. `force_rerun` remains accepted as a redundant compatibility flag.
- Direct answer evaluation also creates unique attempt-local cache directories. It reads no persisted cache and performs no in-memory retrieval/generation/judge replay, including duplicate selected queries. Existing cache-enable flags control only writing local diagnostic records.
- New cache envelopes use fixed `schema_version: 3`, `cache_contract_version: 1`, `mode: fresh`, and `reusable: false`; old cache files are not modified. The older settings cache-schema value does not select this new envelope contract. No supported replay mode is introduced in this slice.
- Assessment `reuse_cached_dataset`/CLI `--reuse-cached-dataset` fails before stages run, with guidance to supply an explicit dataset path. Selecting a file is not proof it is frozen/reviewed. The standalone dataset-builder legacy lookup is not redesigned or certified here.
- Cancellation propagates without publishing successful caches. Successful finite metric records can be written diagnostically; transient errors do not become successful reusable entries. Optional cache-directory/serialization/I/O errors preserve already-computed rows/measurements and record a neutral `cache_policy.write_status: failed`, without exception details in logs/returned diagnostics.
- **Behavior/cost change:** repetition no longer silently avoids generation/judging by deduplication. Real execution can incur new work/cost; this implementation approval does not authorize that work. Fresh attempts are not controlled cold/warm benchmark samples: index/process/SDK/evaluator isolation and timing gates remain open.

### Atomic publication and readers

- Existing artifact JSON/JSONL/text, run-index, latest-pointer, and answer-cache writers stage complete content into unique sibling temporary files and publish with `os.replace`. Serialization/write/replace failures preserve the old destination; temporary files are cleaned on ordinary failure paths. JSON/JSONL serialization rejects non-finite values.
- Finalization evaluates measurement/quality failure first, then represents non-finite diagnostic metric values as JSON `null`, including nested retrieval/answer traces, step findings and aggregate/ablation diagnostics. Invalid required measurements remain incomplete/failed; strict JSON writing does not turn them into scores or lose the failure summary.
- Atomicity is one local file's old-or-new visibility, not an all-files transaction, fsync/power-loss durability, a hard cancellation boundary, shared cache merging, or safe mutable-index sharing. Concurrent publication is last-writer-wins; no shared cross-process writable replay cache is authorized.
- Existing artifact filenames remain readable. Payload/history readers add `legacy`, `versioned`, or `unsupported` compatibility labels and `comparable: false`, without rewriting historical artifacts. Recognizing version 1 is not proof of semantic comparability. Older reader/dashboard aggregates and exploratory winner selection are not converted into verified comparisons by these labels.
