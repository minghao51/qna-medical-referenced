## Implementation and explicit behavior corrections

- `src/config/context.py`: use the existing overlay for copied `retrieval_overrides`, `indexing_features`, and the successfully applied profile name. Reset clears them; snapshots copy the new dictionaries.
- `src/rag/{config,index,production_profile}.py`: configuring an experiment installs a copy of its retrieval options, replacing the previous run/profile overlay. Successful profile application records its name; unknown/no-op application does not pretend to apply it. Shared resolution is static settings → active profile/run → non-None explicit options. Enabled adaptive query routing sits above the base profile but below explicit request controls. False disables stay false; None inherits. Settings-backed HyDE length/enabling and reranking mode are now honored.
- `src/rag/runtime.py`, `src/usecases/chat.py`, `src/app/routes/chat.py`: omitted/None top-k inherits the effective configuration; explicit integers take priority, clamped to at least one consistently for empty/nonempty sync/async retrieval. The chat route no longer unconditionally supplies five. Zero MMR stays zero; zero/negative count controls clamp to one rather than falling through to a static default.
- `src/experiments/config.py`: experiment-file defaults exclude any already-active run/profile, avoiding cross-run default contamination. The evaluation adapter forwards the requested retrieval mapping, not a partial whitelist with fabricated false defaults, so thresholds/other optional controls and omission survive to the common resolver.
- `src/cli/eval_pipeline.py`: config-mode retrieval merges only explicitly supplied retrieval flags; reranking mode/enabling and top-k no longer get lost. Unrelated flags no longer inject a default hybrid search. Mode aliases, `disable_bm25`, and top-k agree between top-level arguments and retrieval options. Explicit `--retrieval-mode` wins over `--search-mode` when both are supplied; explicit `--disable-bm25` wins both. Standalone defaults and the existing flag surface are unchanged.
- `src/ingestion/{runtime_config,pipeline}.py`: typed ingestion configuration copies features directly into `RuntimeState`, then `IngestionRunConfig.from_runtime_state()` reads them. **The store factory/constructor is unchanged** and is not a generic feature transport.
- `src/ingestion/steps/_utils.py`: a zero/nonpositive sampling rate or nonpositive chunk cap selects nothing. Positive tiny rates retain the historical minimum-one sampling behavior. Previously a zero rate still generated one chunk; this is a deliberate correction.
- `src/ingestion/nodes/enrich.py`: documentation explicitly retains the existing DashScope/Qwen client dependency for index-time HyPE/keywords/summaries. No role migration or new model client was added.
- `src/usecases/runtime_config.py`, `src/app/routes/config.py`, and generation trace updates in `src/usecases/chat.py`: distinguish applied versus configured/requested profile; use the injected client's model when a string, or the selected provider's configured default model otherwise. Index-time flags come from the ingestion overlay, are labeled `next_build`, and expose the retained Qwen role separately from generation.

**Ranking warning:** the selected default profile string is unchanged, but `baseline_cross_encoder` now actually invokes reranking. Historical rankings/metrics from the broken path are not the corrected control benchmark. No live quality comparison was performed.
